# CosmoEdge Connect summary report Read projection

This optional plugin supports report-hook development tests. It is not part
of the current default report workflow or required for MCP. See the current
[installation guide](../../../../docs/installation.md).

This directory is a local WorkBuddy marketplace. Its one plugin uses a command-type
`PostToolUse` hook matched only to `Read`. It never changes the original report,
`present_files`, another tool or a non-target Read. It has no Stop hook, model
override, agent, Skill frontmatter hook, subprocess, network connection or runtime
state. The Python hook reads only its bounded stdin, the target report/provenance
and its own packaged candidate identity. It writes only a replacement tool result
to stdout and never logs input, report content, credentials or history.

## Paired build contract

Copy this complete marketplace directory into the paired bundle. It contains:

```text
.codebuddy-plugin/marketplace.json
plugins/cosmoedge-summary-report-guard/
  .codebuddy-plugin/plugin.json
  hooks/hooks.json
  scripts/post_read.py
  candidate.json                 # injected by the paired builder
```

The market is `cosmoedge-summary-report-guard-local`; the plugin is
`cosmoedge-summary-report-guard`. Both source manifests use template version `0.1.0`.
The builder must assign the plugin and marketplace entry the same candidate-specific
version and hash all resulting files. It must inject the following strict shape in
the plugin root's `candidate.json`, using the same identity as the paired client:

```json
{
  "schemaVersion": 1,
  "candidate": {
    "product": "cosmoedge-connect",
    "version": "synthetic-version",
    "revision": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "modified": false,
    "platform": "darwin/arm64"
  }
}
```

This example is synthetic; no candidate identity is committed with the source.
The generated file must be regular, owned by the current user, not a symlink and
not group/other writable. Missing or mismatched identity cannot produce ready text.

## Report contract

Only `cosmoedge-summary-<random>/统计报告.md` directly under an OS standard temp
root is a target: `/tmp` (including its canonical alias) and the OS-reported Darwin
per-user temp root. Arbitrary `TMPDIR` overrides are not trusted anchors. The client
uses its default `tempfile.mkdtemp(prefix="cosmoedge-summary-")` location. This current
implementation requires POSIX ownership/mode and descriptor-relative no-follow APIs.

The directory must be current-user-owned mode `0700`. The report and adjacent
`report-provenance.json` must be current-user-owned, regular `0600`
files. Relative symlinks, directory symlinks, noncanonical paths and changed files
are rejected. The exact provenance keys are:

```text
schemaVersion = 1 (integer, not boolean)
kind = "cosmoedge_summary_report"
reportFile = "统计报告.md"
sha256 = lowercase SHA256 of the original UTF-8 bytes
sizeBytes = original byte length (integer, not boolean)
contentType = "text/markdown; charset=utf-8"
candidate = exactly the five fields shown above
```

Duplicate JSON keys and extra metadata keys are rejected. Provenance/candidate JSON
is capped at 4 KiB; the report cap is **256 KiB**, matching the operations client.
The hook compares all five candidate fields with its paired identity and checks the
report's size/hash/UTF-8 bytes using no-follow file descriptors and readback identity.

Target recognition happens before provenance validation. An old target report with
missing provenance, or any target integrity/permission/candidate failure, gets a
fixed verification-unavailable message with no report body or attachment path.
A verified target gets only a fixed non-statistical notice, its original path, and
the requirement to actually use native `present_files` before claiming delivery.
No totals, date range, source grouping or inferred coverage are generated by the hook.

## Input and host boundaries

Hook stdin is capped at 1 MiB. A damaged/oversized native envelope can still be
recognized from its preceding metadata (first 16 KiB, before `tool_response`), and
a recognized target receives the unavailable replacement. If malformed transport
cannot identify a target at all, the hook emits nothing; it must not globally
replace unrelated Read results. Native envelope shape and capacity must therefore
be verified during candidate qualification. No original input is written to logs.

This is a tool-result projection, not an OS adversary boundary, a filesystem
sandbox, a final-message template or a fail-closed host extension. Renamed/copied
files, Bash, other tools, disabled hooks and host/plugin execution failures are
outside its interception contract. Successful report preparation does not prove
native delivery or prove that the host's later answer is accurate. Installation,
exact plugin-byte readback and a fresh native report Read/`present_files` test are
required candidate evidence. No production/native acceptance is claimed by unit tests.

Official mechanisms: [WorkBuddy plugins](https://www.codebuddy.cn/docs/workbuddy/Plugins),
[PostToolUse output replacement](https://www.codebuddy.cn/docs/cli/hooks), and
[local marketplace loading](https://www.codebuddy.cn/docs/cli/plugin-marketplaces).

Run only the focused synthetic tests with:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s integrations/workbuddy/tests -p test_summary_report_hook.py -v
```
